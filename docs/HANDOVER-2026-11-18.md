## The open bug (start here)
Two engines on one shared channel that also hears itself (test helper `bus_engines` in
`kahf-daemon/src/lib.rs` tests) never deliver a message:
- `one_message_over_an_echoing_channel_arrives_once` and
  `several_messages_each_way_all_arrive_once_in_order_and_none_from_self` fail: link reaches Connected
  after ~10 s but no `Event::Message` arrives; the link goes Idle later. Run with
  `KAHF_TRACE=1 cargo test -q -p kahf-daemon one_message_over_an_echoing -- --nocapture` to see events.
- The older tests with separate pipes (no echo) pass, so the difference is the echo bus. Hypotheses to check,
  in order: (1) the 400 ms `rx_deaf_until` discards the peer's immediate reply (in the bus, samples arrive
  ahead of real time); (2) draining the input in `end_rx_gap` throws away the first part of a reply;
  (3) both stations start calling each other at t=0 (simultaneous open) and the MAC/backoff then lock-steps;
  (4) data bursts are sent without a MAC check once queued (`bursts` queue) and collide with answers;
  (5) own frames still reach the link (DATA frames carry no callsign), so make the echo discard exact
  (discard by sample timestamp of our own transmission, not by wall clock).
Compare with the real behaviour: the owner's BlackHole setup is exactly this echo case.
